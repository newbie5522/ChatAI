# NewbieChat V2 总体开发计划

> 本文件定义不可由单个执行者私自改变的产品方向与架构边界。状态以 GitHub Issues/PR 为准。

## 目标

把当前以浏览器会话状态为中心的聊天前端，升级为服务端持久化、可恢复、可观测的多模型 AI 会话平台。目标体验包括：即时发送、稳定流式输出、停止与重试、消息分支、刷新恢复、持久附件、连续生图/视频以及可诊断错误。

## 核心边界

1. 服务端是 Conversation、Message、Run、Attachment、Artifact 与 Usage 的唯一事实源。
2. UI 不直接理解供应商协议，只消费统一运行时事件。
3. Model Gateway 按能力注册，不按 provider 名称猜测能力。
4. 文件与媒体产物必须持久化，不依赖浏览器 Base64、临时 URL 或进程内存。
5. 摘要、解析、OCR、生图和视频均不得阻塞用户消息落库。
6. 所有外部调用必须有 request_id、超时、取消、幂等、错误分类与用量结算。
7. V2 通过功能开关灰度，不采用一次性推倒重写。

## 当前执行顺序

- 并行启动 #14 与 #15，但不得同时修改同一文件；发生重叠时 #15 的网关边界优先，#14 的 UI 恢复边界优先。
- #16 的设计可以并行评审，但实现合并必须在 S0 完成后。
- #17、#18、#19、#20、#21 暂不进入实现，允许做只读调研和 ADR 草案。
- 禁止绕过 S1 直接把更多状态塞进现有 localStorage。

## 非目标

- 不复制 ChatGPT 私有源码或数据库。
- 不直接复制 Cherry Studio AGPL 代码。
- 不以恢复旧设置页面全部功能为目标。
- 不用“大重构”作为缺少测试和迁移方案的理由。
