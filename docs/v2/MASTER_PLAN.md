# NewbieChat V2 项目总计划（无日期门禁版）

> 本文件定义产品目标、真实完成度、执行顺序和验收门禁。  
> GitHub main、Issue、PR、CI、验收报告是唯一事实源；聊天声明、未推送代码和本地测试不能把任务标记为 DONE。  
> 本计划刻意不写预计完成日期、工期或速度承诺，避免执行模型为赶时间跳过依赖与验收。

## 1. 项目目标

把当前以浏览器状态为中心的聊天应用，升级为服务端持久化、可恢复、可观测、支持多模型与连续媒体创作的生产系统，同时保留员工/管理员账号、权限、额度上限、Provider 凭证和模型路由。

### 需要完整交付的功能

| 功能域 | 最终要求 | 禁止的临时实现 |
|---|---|---|
| 基础对话 | 即时发送、稳定流式输出、停止、重试、重新生成、消息分支 | 重复消息、空助手消息、永久“处理中” |
| 运行恢复 | 刷新、断网、重连和服务重启后恢复消息与 Run | 仅靠 React 状态或浏览器内存 |
| 会话数据 | Conversation、Message、MessagePart、Branch、Run 由服务端持久化 | localStorage 作为唯一事实源 |
| 多模型网关 | UI 只消费统一事件；Adapter 处理各供应商协议 | UI 按 provider/model 名称硬编码能力 |
| 能力矩阵 | 按 Provider + Model + Endpoint + Input Schema + 实测结果判断能力 | 仅根据模型名或 /v1/models 推断 |
| 图片生成 | 文生图、图生图、参考图、多图、连续编辑；失败可诊断和重试 | HTTP 200 即视为成功、静默退化文生图 |
| 视频生成 | 异步任务、进度、取消、重试、刷新恢复、产物持久化 | 同步阻塞聊天、依赖临时 URL |
| 文件与附件 | 持久上传、解析、OCR、索引、权限、过期和失败重试 | 浏览器 Base64、临时目录或进程内 session |
| 上下文与记忆 | 长对话压缩、摘要和记忆；失败不阻塞用户消息落库 | 摘要先完成才能保存消息 |
| 额度与用量 | reserve/confirm/release 原子账本、幂等、防重复扣费 | 进程内 Map 作为额度事实源 |
| 权限与安全 | 员工/管理员 RBAC、租户隔离、审计、日志脱敏 | 仅依赖前端隐藏按钮或客户端 employeeId |
| 可观测性 | request_id、错误分类、超时、取消、供应商与费用链路 | 向用户泄露密钥或完整上游响应 |
| 发布与回滚 | 功能开关、迁移演练、静态资源兼容、一次性切换和可验证回滚 | 无备份直接迁移、长期双写、作者自行验收 |

## 2. 不可改变的架构边界

1. 服务端是 Conversation、Message、Run、Attachment、Artifact 与 Usage 的唯一事实源。
2. UI 不直接理解供应商协议，只消费统一运行时事件。
3. Model Gateway 按实际能力注册，不按供应商或模型名称猜测能力。
4. 文件与媒体必须持久化，不依赖浏览器 Base64、临时 URL、容器临时目录或进程内存。
5. 摘要、解析、OCR、生图和视频均不得阻塞用户消息落库。
6. 所有外部调用必须有 request_id、超时、取消、幂等、错误分类与用量结算。
7. 架构变更先写 ADR；执行端不得边实现边改变方向。
8. 允许在“上游接口/契约冻结”后有限并行；合并验收门禁不得放宽。
9. 保留账号、凭证、权限、额度上限、Provider 凭证及路由；旧聊天、旧附件、旧媒体和旧用量数据允许放弃。
10. 切换时当前月已用额度清零并记录切换点；不采用长期双跑/双写；回滚可放弃切换期间的 V2 测试数据。
11. 密码、密钥和备份口令不得写入仓库、报告或聊天。

## 5. 阶段报告与暂停点

每个波次完成后必须生成 `docs/v2/reviews/P*_ACCEPTANCE_REPORT.md`，然后暂停后续实现，等待非作者审核。

报告至少包含：

1. main/base/head SHA、Issue、PR 和实际修改文件。
2. 需求逐项对照：通过 / 不通过 / 未验证。
3. 单元、集成、E2E、真实数据库或真实供应商测试命令及结果。
4. UI 截图、关键日志、request_id；内容必须脱敏。
5. 数据库迁移、部署操作和回滚实测证据；无变更时明确写“不适用”。
6. 是否出现供应商硬编码、localStorage/进程内持久状态、空助手消息、额度不一致或安全回归。
7. 未完成项、风险和“下一步唯一动作”。
8. 明确结论：`PASS` / `BLOCKED`，不得使用“基本完成”。

## 6. 并行与合并规则

- 启动门禁：上游 schema/API/事件契约冻结，且任务不修改同一文件、不共享未隔离数据库/端口、可独立测试和回滚。
- 合并门禁：PR head 上 CI 全绿、非作者正式 Review、无越界、证据齐全、回滚明确、需要时取得用户批准。
- 一个 Issue 一个分支；不得把多个阶段塞入同一 PR。
- 执行端不得自行合并高风险 PR，不得用 mock 代替真实数据库、生产线路或并发证据。
- 任何失败测试、缺证据或状态冲突均标记 BLOCKED，不能用文档声明覆盖。

## 7. 非目标

- 不复制 ChatGPT 私有源码或数据库。
- 不直接复制 Cherry Studio AGPL 代码。
- 不以恢复旧设置页面全部功能为目标。
- 不用“大重构”作为缺少测试、迁移和回滚方案的理由。
- 不为了赶排程添加未经验证的临时持久状态。
